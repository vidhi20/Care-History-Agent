# Care History Agent

**An AI assistant that reads family caregivers' daily notes about a person living with dementia and turns them into a clear symptom timeline for the care team.**

Caregivers write things like *"Dad tried to leave the house twice tonight and barely touched his dinner."* Doctors and nurses rarely have time to read weeks of free-text notes. This agent, built on Claude, pulls out each symptom, quotes the sentence that shows it, and flags anything **new** since earlier notes, so a clinician can see what changed at a glance.

> All patients and notes in this repo are **synthetic** (generated by `data/generate_notes.py`). No real patient data is used.

## What it does

```
Caregiver note (free text)
        │
        ▼
Claude agent ──► tool: get_patient_history   (what has this patient shown before?)
        │
        └──────► tool: record_symptoms        (category + evidence quote + is_new flag)
        │
        ▼
Care timeline (per patient, per week, NEW changes highlighted)
```

- **10 symptom categories:** memory loss, confusion, agitation, sleep problems, wandering, appetite change, falls, low mood, hallucinations, communication trouble
- **Tool calling:** the agent checks the patient's history first, then records what it found, so "new" flags stay consistent over time
- **Evidence quotes:** every symptom links back to the caregiver's own words, so a clinician can trust and check it
- **Keyword baseline:** a simple rule-based extractor for comparison and for running the project without an API key

## Example output

```
## 2026-01-19
- memory loss: "didn't remember eating lunch an hour after we ate together"
- appetite change **NEW**: "barely touched her dinner again"
```

## How it's measured

`eval/evaluate.py` runs every note through the agent, in date order per patient, and compares against hand-set labels:

| Metric | What it means in plain words |
|---|---|
| Recall | Share of real symptoms the agent caught |
| Precision | Share of the agent's flags that were correct |
| F1 | One score that balances the two |
| New-change F1 | How well it spots symptoms that are new for that patient |
| Fully correct notes | Notes where every symptom and every "new" flag was right |

## Results

Scored on all 50 labeled synthetic notes. Results are saved to `results/`.

| Runner | Symptom recall | Symptom precision | Symptom F1 | New-change F1 | Fully correct (of 50) |
|---|---|---|---|---|---|
| Keyword baseline | 88% | 100% | 93.6% | 89.2% | 39 |
| Claude agent | Not scored yet | Not scored yet | Not scored yet | Not scored yet | Not scored yet |

The keyword baseline is the reference point the agent has to beat. Its weakest category is memory loss (76.9% F1), because caregivers describe forgetting in many different ways that fixed keywords miss. That is the gap the Claude agent is built to close.

The Claude agent row needs a paid Anthropic API key to run. Run `python eval/evaluate.py` with a key to fill it in; scores are written to `results/metrics_agent.json`.

## Run it

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=your-key          # Windows: set ANTHROPIC_API_KEY=your-key

python data/generate_notes.py              # create the 50 synthetic notes
python eval/evaluate.py                    # score the Claude agent
python eval/evaluate.py --mock             # score the keyword baseline (no key needed)
python run_demo.py P003                    # print one patient's care timeline
```

Set `CLAUDE_MODEL` to choose a different Claude model (default `claude-sonnet-5-5`).

You can also copy `.env.example` to `.env` and put your key there; the agent reads it automatically. If your key belongs to a whole organization rather than one workspace (common with university accounts), also set `ANTHROPIC_WORKSPACE_ID` to your workspace ID from Console > Settings > Workspaces.

## Project structure

```
agent/
  agent.py      Claude tool-calling loop
  schema.py     symptom categories and tool definitions
  history.py    per-patient care history and timeline
  baseline.py   keyword baseline for comparison
data/
  generate_notes.py   builds 50 labeled synthetic notes (10 patients x 5 weeks)
eval/
  evaluate.py   precision, recall, F1, new-change F1, fully-correct count
run_demo.py     prints a patient's timeline
```

## Limits and next steps

- Synthetic notes are cleaner than real ones. The next test is messier, longer notes with typos and mixed topics.
- Categories are fixed. A next step is adding severity (mild or severe) and how often a symptom appears.
- This is a decision-support prototype, not a medical device, and it gives no medical advice.
